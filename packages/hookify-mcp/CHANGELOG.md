# @altalyst/hookify-mcp

## 0.1.3

### Patch Changes

- [#154](https://github.com/altalyst-solutions/hookify/pull/154) [`76fb84b`](https://github.com/altalyst-solutions/hookify/commit/76fb84bbf92981e517c20d216b6c41c1f4eabed5) Thanks [@sleepinzombie](https://github.com/sleepinzombie)! - `@altalyst/hookify/testing` now also fakes the Web Locks API and `BroadcastChannel`, so components that use `useWebLock` or `useTabLeader` can be tested. `installWebLocks()` replaces `navigator.locks` with an in-memory lock manager that follows the real queueing rules: requests are granted in order per name, shared locks run together, `ifAvailable`, `steal` and an abort `signal` work, and invalid option combinations reject. Its controller lists the `held` and `pending` locks and every `request`, `hold(name, mode)` takes a lock as another tab would and returns a `release()`, `releaseAll()` frees locks, and `failNext()` makes the next request reject. `installBroadcastChannel()` replaces `BroadcastChannel` with a fake that delivers structured clones to other open channels with the same name, never back to the sender. `peer(name)` returns a stand-in for another tab that can `post()` messages and records what it `received`. Both return a controller with `restore()`.

- [#152](https://github.com/altalyst-solutions/hookify/pull/152) [`c1c03f9`](https://github.com/altalyst-solutions/hookify/commit/c1c03f946395743b45fb791064a654e7ff929650) Thanks [@sleepinzombie](https://github.com/sleepinzombie)! - `@altalyst/hookify/testing` now also fakes `matchMedia` and the document's visibility. `installMatchMedia({ matches })` replaces `window.matchMedia`: `setMatches(query, matches)` changes a query and fires `change` on its lists, which support both `addEventListener` and the deprecated `addListener`. `installDocumentVisibility({ visibilityState })` controls `document.visibilityState` and `document.hidden`, and `setVisibility(state)` fires `visibilitychange`. Both expose `listenerCount`, `listenersAdded` and `listenersRemoved`, so a test can check that a component subscribes and cleans up, and both return a controller with `restore()`.

- [#153](https://github.com/altalyst-solutions/hookify/pull/153) [`b9ddd13`](https://github.com/altalyst-solutions/hookify/commit/b9ddd1337dfed8970b122d26be013c5cf1be4ccb) Thanks [@sleepinzombie](https://github.com/sleepinzombie)! - `@altalyst/hookify/testing` now also fakes web storage and the clipboard. `createMemoryStorage()` is an in-memory `Storage` that can enforce a `quota` and throw a real `QuotaExceededError`; `installLocalStorage()` and `installSessionStorage()` put one on the window, and can make the global throw a `SecurityError` as when storage is blocked. `dispatchStorageEvent(key, newValue, storage)` simulates another tab changing storage, so cross-tab sync can be tested without writing events by hand. `installClipboard()` replaces `navigator.clipboard`, records what was written, can deny permission with a `NotAllowedError`, and can fail or hold calls in flight with `failNext()` and `deferNext()`.

- [#149](https://github.com/altalyst-solutions/hookify/pull/149) [`5245307`](https://github.com/altalyst-solutions/hookify/commit/52453075020a2f5631649334968b133b12196f23) Thanks [@sleepinzombie](https://github.com/sleepinzombie)! - Adds `@altalyst/hookify/testing`, a separate entry with test helpers that don't depend on any test runner. It starts with fakes for `IntersectionObserver` and `ResizeObserver`, which jsdom doesn't implement: `installIntersectionObserver()` and `installResizeObserver()` put a fake on the global and return a controller to `trigger()` entries, inspect the observers that were created, and `restore()` the global. `createIntersectionObserverEntry()` and `createResizeObserverEntry()` build entries for tests. The main `@altalyst/hookify` bundle is unchanged.

- [#155](https://github.com/altalyst-solutions/hookify/pull/155) [`70b41ea`](https://github.com/altalyst-solutions/hookify/commit/70b41eaa2f1fce62773ce35e00f50e321f085cf0) Thanks [@sleepinzombie](https://github.com/sleepinzombie)! - `get_hook` now lists the fakes from `@altalyst/hookify/testing` that a hook needs in a test, such as `installIntersectionObserver` for `useIntersectionObserver` or `installWebLocks` and `installBroadcastChannel` for `useTabLeader`, so an agent writing tests for a component that uses the hook reaches for the fake instead of writing a mock by hand.

## 0.1.0

### Minor Changes

- [#127](https://github.com/altalyst-solutions/hookify/pull/127) [`7bc9241`](https://github.com/altalyst-solutions/hookify/commit/7bc9241ba609d0a003d610d2bb27fea9041a83b1) Thanks [@sleepinzombie](https://github.com/sleepinzombie)! - First release of `@altalyst/hookify-mcp`, an MCP server that gives AI coding agents accurate, version-matched docs for `@altalyst/hookify`, so they use the real API instead of guessing it. Add it to your agent with `npx -y @altalyst/hookify-mcp` (for example `claude mcp add hookify -- npx -y @altalyst/hookify-mcp`). It offers three read-only tools: `list_hooks` lists every hook in a line each, grouped by category; `get_hook` returns a hook's signature, parameters, option and return types with defaults, use cases, behavior details and an example; and `find_hook` recommends hooks for a problem described in plain language, such as "debounce a search input", with the use case each one fits. It runs locally over stdio, makes no network requests, needs Node.js 22 or later, and starts every response with a note when your project has a different `@altalyst/hookify` version installed than the one its docs describe.
