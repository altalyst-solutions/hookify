# useApi

Performs an HTTP request and manages its `loading`, `data`, and `error`
states for you, along with a `refetch` function to manually re-run the
request.

## When to use it

- Fetching data from a REST endpoint on mount and rendering loading/error UI.
- Supporting custom HTTP methods, headers, or request bodies.
- Giving users a way to manually refresh fetched data.

## Signature

```ts
function useApi<T = unknown>(
  url: string,
  options?: UseApiOptions
): UseApiReturn<T>;

interface UseApiOptions {
  method?: "GET" | "POST" | "PUT" | "PATCH" | "DELETE";
  headers?: HeadersInit;
  body?: BodyInit;
}

interface UseApiReturn<T> {
  data: T | null;
  loading: boolean;
  error: Error | null;
  refetch: () => Promise<void>;
}

class ApiError extends Error {
  readonly status: number;
  readonly response: Response;
}
```

| Parameter | Type            | Description                                         |
| --------- | --------------- | --------------------------------------------------- |
| `url`     | `string`        | The endpoint to fetch data from.                    |
| `options` | `UseApiOptions` | Optional method, headers, and body for the request. |

**Returns:** `{ data, loading, error, refetch }`

## Usage notes

- The request automatically re-runs whenever `url`, `method`, `headers`, or
  `body` change.
- The response body is parsed as JSON automatically. `204` and `205` (No
  Content) responses resolve to `null` without parsing.
- Only the latest request can update the state. When the inputs change,
  `refetch` runs again, or the component unmounts, the request in flight is
  aborted with an `AbortSignal` and its result is ignored, so a slow,
  outdated response never overwrites a newer one.
- `error` is an `Error`. A non-2xx response is reported as an `ApiError`
  with the `status` and the unread `response`, so you can branch on the status
  code or read an error body. Network failures and JSON parse errors are
  reported as the original `Error`.
- `UseApiOptions`, `UseApiReturn` and `ApiError` are exported for typing your
  own wrappers.

## Handling errors

```tsx
const { data, error } = useApi<User>("/api/user");

if (error instanceof ApiError && error.status === 401) {
  return <SignInPrompt />;
}
if (error) {
  return <p>Something went wrong: {error.message}</p>;
}
```

### Migrating from 0.11

`error` used to be a `string` such as `"Error: 404"`. Render `error.message`
instead of `error`, and check `error instanceof ApiError` with `error.status`
instead of parsing the status out of the string.

- `refetch` re-triggers the same request on demand — handy for "Retry" or
  "Refresh" buttons.
